# Decisions

Rulings made while building binscope, in the format
`Ruling: <what> — <why> — <cost if wrong>`.

## Scope

- Ruling: implement **both** ssdeep and TLSH although the brief asked for "TLSH or ssdeep" — they fail in opposite ways (ssdeep survives large contiguous edits but collapses under scattered edits; TLSH the reverse, see README evaluation), and clustering/compare are more useful with both — cost if wrong: ~600 extra lines to maintain.
- Ruling: support ELF, PE (PE32/PE32+) and Mach-O including universal binaries; COFF objects, TE images and `ar` archives are detected and reported as unsupported containers but still hashed and string-scanned — keeps the format layer focused on executables analysts actually triage — cost if wrong: no per-member analysis of static libraries.
- Ruling: binscope is strictly static: no emulation, unpacking or execution — defensive scope required by the program contract and avoids building packer/evasion tooling — cost if wrong: packed samples show only their outer layer.

## Correctness and verification

- Ruling: verify against the real tools by committing their outputs as TSV vectors generated by `scripts/reference/` (which builds ssdeep 2.14.1, TLSH 4.12.1 and pefile 2024.8.26 in a temp dir from checksummed sources) — `make check` stays offline and deterministic while the vectors are reproducible — cost if wrong: refreshing vectors needs network and a C/C++ toolchain.
- Ruling: synthetic reference inputs are regenerated in the tests from `(kind, size, seed)` encoded in their names instead of being committed — 132 inputs up to 3.5 MB would otherwise add ~25 MB to the repo — cost if wrong: changing `synth::generate` invalidates the vectors (the generator is covered by determinism tests).
- Ruling: copy TLSH's `v_table` and `topval` tables from the reference source via a generator script rather than re-deriving them — the paper fixes the algorithm, but bit-exact digests need identical constants (`topval` replaces float `log()` to avoid platform drift) — cost if wrong: none for correctness; the tables are Apache-2.0/BSD data, attributed in DATA.md.
- Ruling: reproduce libfuzzy 2.14 behaviour exactly, including the block-size elimination that depends on the declared total size and the small-block-size score cap — users compare binscope digests with ssdeep output in the wild — cost if wrong: n/a (verified on 253 digests and 1,587 comparisons).
- Ruling: imphash only for PE, matching pefile's `get_imphash()` including its ordinal tables for ws2_32/wsock32/oleaut32; ELF and Mach-O get **symhash** (MD5 of sorted, de-duplicated imported symbol names, the CRITs Mach-O definition) — imphash has no agreed ELF/Mach-O definition, and an order-free hash suits formats whose import order is linker-defined — cost if wrong: symhash values are not validated against an external tool.

## Parsing

- Ruling: decode `LC_DYLD_CHAINED_FIXUPS` imports in-house because goblin 0.10 ignores them — every arm64 binary linked for macOS 12+ would otherwise report zero imports — cost if wrong: ~100 lines of format parsing to maintain (cross-checked against llvm-nm on all fixtures).
- Ruling: attribute ELF imports to libraries via `.gnu.version_r` and leave unversioned imports unattributed — ELF has no per-symbol library binding otherwise — cost if wrong: library-qualified rules (`libc!puts`) do not match unversioned ELF imports (unqualified rules do).
- Ruling: report Mach-O symbol names as stored (leading underscore) but match rules on the underscore-stripped name — keeps evidence faithful to the binary while letting one rule cover all formats — cost if wrong: a rule targeting a genuinely underscore-prefixed C symbol must include the extra underscore.
- Ruling: universal Mach-O files are analysed per slice; rules see the union of slices; fuzzy hashes cover the whole file — mirrors how analysts reason about a fat binary — cost if wrong: no per-slice similarity scores.
- Ruling: catch panics from the container parser and convert them to per-file parse errors — one hostile sample must not abort a batch — cost if wrong: an abort (OOM) still cannot be caught.
- Ruling: PE section entropy is computed over the raw section (`PointerToRawData`, `SizeOfRawData`) exactly as pefile does, including file-alignment padding — matches the reference tool to 1e-9 — cost if wrong: padding lowers measured entropy of small high-entropy sections (packed PE fixtures read ~7.6 instead of ~7.96).

## Heuristics and rules

- Ruling: high-entropy threshold 7.2 bits/byte over at least 256 bytes (anomaly) / 1 KiB (built-in packing rule) — the conventional cut-off (Lyda & Hamrock, IEEE S&P 2007) — cost if wrong: false positives on embedded compressed resources (images, archives).
- Ruling: rules are YAML deserialised with `serde_norway` (maintained fork of the deprecated `serde_yaml`) using `singleton_map_recursive`, so leaves read `import: socket` rather than YAML tags — friendlier to write and diff — cost if wrong: dependency on a smaller fork.
- Ruling: strict rule validation (unknown keys, unknown string tags or anomaly ids, empty combinators, bad regex, duplicate ids, nesting > 32) fails the load with file + rule id — silent typos in detection content are worse than a loud error — cost if wrong: older rule files with extra keys need editing.
- Ruling: ATT&CK ids in built-in rules are coarse labels only — no claim of ATT&CK coverage — cost if wrong: none.
- Ruling: UTF-16 extraction accepts only ASCII-range code units — avoids floods of garbage "strings" from binary data — cost if wrong: misses non-Latin UTF-16 text.

## Clustering

- Ruling: default thresholds TLSH distance <= 70 and ssdeep score >= 40 were fixed **before** running the evaluation (rule-of-thumb values: lower TLSH distances are more conservative and ~100 is a commonly quoted "similar" boundary; ssdeep scores in the 40s+ are commonly treated as meaningful), and the README reports a sensitivity sweep rather than tuning on the same corpus — avoids reporting tuned numbers — cost if wrong: defaults are not optimal for a given corpus; `--threshold` overrides them.
- Ruling: single-linkage connected components with a union-find, plus exact candidate pruning (ssdeep 7-gram index, TLSH length-bucket bound) instead of approximate indexes — results are exactly reproducible and testable against brute force; 10^3–10^4 samples are well within budget — cost if wrong: very large corpora (10^6) would need a metric index (e.g. VP-tree) for TLSH, whose length bound prunes only ~25% of pairs on similarly sized files.
- Ruling: evaluate clustering against two labelings from the manifest (program+target, program only) and add a synthetic edit-robustness study — the fixture corpus alone cannot show *why* fuzzy hashes succeed or fail — cost if wrong: synthetic edits are a model of real code changes, disclosed as such.

## Fixtures

- Ruling: build the corpus from freestanding C with clang + rust-lld (stub `libc.so.6`, import libraries from `.def` files) on macOS instead of using cross toolchains or downloaded binaries — real ELF/PE/Mach-O with real dynamic imports, fully reproducible from the repo, no third-party binaries — cost if wrong: binaries are tiny (2–66 KB), so boilerplate dominates and fuzzy-hash results on them are not representative; rebuilding requires macOS (`lipo`).
- Ruling: import ws2_32 functions by ordinal in the PE builds — exercises the pefile ordinal mapping in imphash — cost if wrong: none.
- Ruling: arm64 Mach-O builds target macOS 12 (chained fixups) and x86_64 builds macOS 10.15 (classic bind opcodes) — covers both import encodings — cost if wrong: none.
- Ruling: the "compressed variant" stores its data blob zlib-compressed in a dedicated section with no unpacking stub, paired with an otherwise-identical plain-text variant — shows the entropy change without writing a packer — cost if wrong: the packer-layout rule is exercised only by unit tests with synthetic section layouts, not by a real packed binary.
- Ruling: commit the built fixtures (2.0 MB) plus a sha256 manifest — `make check` must not need clang/lld — cost if wrong: repository size.

## Engineering

- Ruling: whole-file passes (digests, ssdeep, TLSH, strings) run on `std::thread::scope` workers for inputs >= 1 MiB — 4 independent O(n) passes; no new dependency — cost if wrong: thread overhead on mid-sized files (threshold keeps small files single-threaded).
- Ruling: MSRV 1.85 (`Option::is_none_or`), edition 2021 — current stable features without nightly — cost if wrong: older toolchains cannot build.
- Ruling: coverage gate = 85% of lines over the whole crate (generated tables excluded), measured with cargo-llvm-cov — the contract asks for >= 80% of core logic; the whole-crate figure is stricter — cost if wrong: `make check` requires cargo-llvm-cov installed.
- Ruling: `--fail-on` uses exit status 3, distinct from errors (1) and usage (2) — CI can tell "findings" from "broken run" — cost if wrong: none.
- Ruling: JSON names Mach-O formats `macho` / `macho-fat`, the same strings rule files use — one vocabulary — cost if wrong: none.
